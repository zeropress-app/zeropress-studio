# Maintenance & Recovery database artifacts

[`001_uninstall.sql`](001_uninstall.sql) removes the Studio-owned schema and
rows. Use it through [Uninstall Studio](../../docs/maintenance-and-recovery.md#uninstall-studio)
after retaining a backup; do not apply it manually to local or remote D1.

The Worker checks the installed catalog against the artifact, executes one
atomic D1 batch, and verifies the uninstalled state. Unknown or missing
application tables block the operation. Managed FTS5 shadow tables are removed
with their virtual tables, and the lifecycle singleton is dropped last.

The operation-specific requirements and data effects are documented in one
place:

- [Clear site content](../../docs/maintenance-and-recovery.md#clear-site-content)
- [Reset Studio](../../docs/maintenance-and-recovery.md#reset-studio)
- [Uninstall Studio](../../docs/maintenance-and-recovery.md#uninstall-studio)
- [Uninstall Edge database](../../docs/maintenance-and-recovery.md#uninstall-edge-database)

SQL backup files are generated by the Worker rather than stored in this
directory. Use [D1 SQL backup and restore](../../docs/maintenance-and-recovery.md#d1-sql-backup-and-restore)
for supported formats, interruption handling, and the separate R2 backup boundary.
